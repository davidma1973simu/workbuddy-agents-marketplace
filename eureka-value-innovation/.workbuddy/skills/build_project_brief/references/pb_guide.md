# Project Brief 参考指南

## 核心设计挑战的撰写原则

### 格式
如何为[目标用户]设计[目标成果]，以[核心价值]？

### 示例

**良好示例**:
- "如何为职场新员工设计一个入职引导系统，以加速他们的角色融入和技能成长？"
- "如何为中小企业设计一个低成本营销工具，以提升他们的品牌曝光和客户获取效率？"

**不佳示例**:
- "做一个入职系统"（太宽泛）
- "设计一个营销工具"（缺乏目标和价值）

## 共识目标的SMART原则

**S** - Specific（具体）：目标必须明确具体
**M** - Measurable（可衡量）：目标必须有可量化的指标
**A** - Achievable（可实现）：目标必须现实可行
**R** - Relevant（相关）：目标必须与核心挑战相关
**T** - Time-bound（有时限）：目标必须有明确时间限制

### 示例
- ✅ "在3个月内，将工作回顾目标清晰度从40%提升到80%"
- ❌ "提升目标清晰度"（不可衡量，无时限）

## 利益相关方类型

### 决策者（Decision Makers）
- 有权决定项目方向和资源分配
- 关注：投资回报、战略价值、风险控制

### 影响者（Influencers）
- 对项目有影响力，但无决策权
- 关注：用户体验、实施可行性

### 执行者（Executors）
- 负责项目实际执行
- 关注：工具易用性、工作量、技能要求

### 受益者（Beneficiaries）
- 最终从项目中获益
- 关注：实际价值、改善效果

## 时间框架设定

### 典型项目周期
- 快速原型: 4-6周
- 试点验证: 8-12周
- 全面推广: 12-24周

### 里程碑设置
每个阶段结束时设置一个里程碑：
- 里程碑1: 需求确认和方案设计
- 里程碑2: 原型开发和测试
- 里程碑3: 试点运行和评估
- 里程碑4: 优化和推广
