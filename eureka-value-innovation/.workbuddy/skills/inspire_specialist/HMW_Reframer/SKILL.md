# HMW_Reframer - HMW机遇重构器

## Skill 概述

**Skill ID**: `HMW_Reframer`
**名称**: HMW机遇重构器
**所属Agent**: Inspire Specialist (启发师)
**任务类型**: 机遇生成

## 功能描述

将用户POV（问题陈述）通过4个维度进行多维度重构，生成6-8个HMW (How Might We) 创新机遇，并通过用户价值和商业可行维度筛选出最佳HMW机遇。

## 核心能力

1. **多维度重构**：从4个不同视角重构用户POV
2. **HMW表述转换**：将问题转化为机遇表述
3. **价值筛选**：从用户价值和商业可行两个维度筛选最佳机遇

## 重构维度详解

### 1. 发挥积极 (Positive)

**核心思想**：从消极问题转向积极可能性，强调"可能"而非"不可能"

**重构策略**：
- 强调积极结果和体验
- 聚焦用户渴望的正面价值
- 将"问题"转化为"机会"

**示例转换**：
```
原POV: "用户不知道该买什么，感到沮丧"
重构: "How might we 让用户每次浏览都能发现新的惊喜？"

原POV: "用户担心买错东西"
重构: "How might we 让用户对每次购买都充满信心？"
```

---

### 2. 去除消极 (Negative Removal)

**核心思想**：识别并消除消极因素，让体验更顺畅

**重构策略**：
- 识别障碍、阻力、摩擦点
- 聚焦如何消除这些消极因素
- 强调"无负担"的体验

**示例转换**：
```
原POV: "用户要在大量产品中花费大量时间"
重构: "How might we 让用户在几秒钟内找到理想产品？"

原POV: "用户被复杂的功能搞得困惑"
重构: "How might we 让产品理解变得简单直观？"
```

---

### 3. 改变假设 (Assumption Change)

**核心思想**：挑战现有假设，从全新视角审视问题

**重构策略**：
- 识别问题背后的隐含假设
- 挑战这些假设
- 提出替代视角

**示例转换**：
```
原POV: "用户需要浏览更多产品才能做决定"
假设挑战: "用户真的需要浏览更多吗？也许他们需要的是更少的、更精准的推荐？"
重构: "How might we 减少用户的选择，但提高选择的准确性？"

原POV: "用户在购物时需要理性比较"
假设挑战: "也许用户更想要情感连接而非理性比较？"
重构: "How might we 购物过程更多是情感体验而非理性决策？"
```

---

### 4. 脑洞大开 (Wild Ideas)

**核心思想**：突破常规限制，大胆设想各种可能性

**重构策略**：
- 忽略现实约束
- 思考最极端的可能性
- 结合新兴技术或未来趋势
- 从其他领域借鉴灵感

**示例转换**：
```
原POV: "用户需要产品推荐"
脑洞1: "How might we 让AI直接预测用户下周需要什么？"
脑洞2: "How might we 用梦境或潜意识推荐产品？"
脑洞3: "How might we 让朋友网络集体为用户推荐？"
脑洞4: "How might we 让产品主动找到用户，而不是用户找产品？"
```

## HMW 表述最佳实践

### 好的 HMW 表述特征
- ✅ 以 "How might we" 开头
- ✅ 聚焦"可能"而非"应该"
- ✅ 开放式，不过于具体
- ✅ 能够激发多种创意
- ✅ 与用户价值相关

### 避免
- ❌ 过于具体（限制了创意空间）
- ❌ 包含解决方案（应该关注问题/机遇）
- ❌ 过于宽泛（失去针对性）
- ❌ 否定式表述

## 筛选评估框架

### 用户价值维度（1-5分）

| 维度 | 评估标准 |
|------|----------|
| **相关性** | 是否解决核心用户痛点？<br>5分 = 直接解决核心痛点<br>1分 = 与核心痛点无关 |
| **新颖性** | 是否带来新的体验或价值？<br>5分 = 全新的价值主张<br>1分 = 常规做法 |
| **易用性** | 用户是否容易理解和使用？<br>5分 = 非常直观<br>1分 = 需要大量学习 |
| **情感价值** | 是否产生情感共鸣？<br>5分 = 强烈情感连接<br>1分 = 无情感价值 |
| **传播性** | 是否值得分享和推荐？<br>5分 = 自然愿意分享<br>1分 = 不值得分享 |

### 商业可行维度（1-5分）

| 维度 | 评估标准 |
|------|----------|
| **技术可行性** | 技术上能否实现？<br>5分 = 技术成熟，易实现<br>1分 = 技术不成熟或不可能 |
| **成本可控性** | 成本是否合理？<br>5分 = 成本低，可控<br>1分 = 成本极高 |
| **市场规模** | 是否有足够的市场空间？<br>5分 = 巨大市场<br>1分 = 极小市场 |
| **竞争差异化** | 是否有竞争优势？<br>5分 = 独特，难以复制<br>1分 = 无差异化 |
| **增长潜力** | 是否有扩展和迭代空间？<br>5分 = 多方向扩展<br>1分 = 无扩展空间 |

---

## 筛选流程

1. **生成阶段**：
   - 从4个维度各生成1-2个HMW机遇
   - 总共6-8个HMW机遇

2. **评估阶段**：
   - 对每个HMW机遇进行用户价值评分（5个维度，每个1-5分）
   - 对每个HMW机遇进行商业可行评分（5个维度，每个1-5分）
   - 计算综合评分：
     ```
     用户价值总分 = (相关性+新颖性+易用性+情感价值+传播性) / 5
     商业可行总分 = (技术可行性+成本可控性+市场规模+竞争差异化+增长潜力) / 5
     综合评分 = (用户价值总分 + 商业可行总分) / 2
     ```

3. **筛选阶段**：
   - 选择综合评分最高的1-2个HMW机遇
   - 确保多样性（不同维度的机遇）
   - 记录筛选理由

## 技术实现要点

### 多维度重构算法

1. **POV分析**：提取核心问题、用户情感、场景特征
2. **维度映射**：为每个维度设计重构模板
3. **HMW生成**：应用模板生成HMW表述
4. **表述优化**：确保HMW符合最佳实践

### 筛选算法

1. **评估打分**：对每个维度进行1-5分评估
2. **综合计算**：计算用户价值总分、商业可行总分、综合评分
3. **排序筛选**：按综合评分排序，选择top 1-2
4. **多样性检查**：确保入选的机遇来自不同维度
