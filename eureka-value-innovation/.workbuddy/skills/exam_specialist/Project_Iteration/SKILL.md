# Project_Iteration - 项目迭代规划师

## 📋 基本信息

- **Skill ID**: `Project_Iteration`
- **Skill 名称**: 项目迭代规划师
- **所属 Agent**: Exam Specialist（验证官）
- **版本**: v1.0.0
- **类型**: 规划类

---

## 🎯 功能定义

**核心功能**：生成项目的概念方案原型的 30-60-90 天迭代计划

**迭代目的**：
- 分阶段验证假设
- 快速迭代优化
- 降低项目风险
- 持续创造价值

---

## 📊 迭代计划结构

### 30 天计划（快速验证阶段）

**目标**：完成 MVP，验证核心功能

**核心原则**：
- 快速：快速开发，快速验证
- 最小：最小可行产品，只做核心功能
- 验证：验证核心假设，收集用户反馈

**关键活动**：
1. **产品开发**
   - 开发 Web 应用原型
   - 实现 AI 推荐模型（基础版）
   - 实现核心功能（智能问答、个性化推荐）

2. **用户测试**
   - 完成 20 位用户测试
   - 收集用户反馈
   - 分析测试数据

3. **数据分析**
   - 分析用户行为数据
   - 分析 AHA 价值
   - 分析商业 MAP 价值

4. **迭代优化**
   - 根据测试结果优化产品
   - 修复 bug
   - 改进用户体验

**关键指标**：
- 功能完成度：100%
- 测试通过率：> 90%
- 用户满意度：> 4/5
- AHA 时刻触发率：> 80%

**里程碑**：
- Day 7：完成 Web 应用原型
- Day 14：完成 AI 推荐模型（基础版）
- Day 21：完成 10 位用户测试
- Day 30：完成 20 位用户测试，输出测试报告

**资源需求**：
- 开发人员：2 人
- 测试人员：1 人
- 开发环境：Web 开发环境、AI 开发环境
- 测试环境：用户测试环境

**风险识别**：
- 技术风险：AI 算法效果不如预期
- 时间风险：开发进度落后
- 用户风险：用户反馈不佳

**应对措施**：
- 技术风险：预留优化时间，考虑备选方案
- 时间风险：定期检查进度，及时调整
- 用户风险：提前收集用户需求，降低预期

---

### 60 天计划（功能完善阶段）

**目标**：功能完善，用户增长

**核心原则**：
- 完善：完善功能，提升体验
- 增长：用户增长，验证商业模式
- 优化：优化算法，提高效果

**关键活动**：
1. **产品迭代**
   - 发布正式版产品
   - 实现 AI 推荐模型（优化版）
   - 增加新功能（对比分析、购买决策）

2. **用户增长**
   - 上线产品推广
   - 获得 1000 用户
   - 建立用户反馈机制

3. **数据分析**
   - 分析用户增长数据
   - 分析用户留存数据
   - 分析商业模式数据

4. **持续优化**
   - 根据用户反馈优化产品
   - 优化 AI 算法
   - 优化用户体验

**关键指标**：
- 用户数：> 1000
- 日活跃率：> 30%
- 用户满意度：> 4.5/5
- 用户留存率：30 天留存率 > 60%

**里程碑**：
- Day 35：发布正式版产品
- Day 45：完成新功能开发
- Day 50：达到 500 用户
- Day 60：达到 1000 用户，输出增长报告

**资源需求**：
- 开发人员：3 人
- 运营人员：2 人
- 市场人员：1 人
- 推广预算：10 万元

**风险识别**：
- 增长风险：用户增长不及预期
- 竞争风险：竞争对手推出类似产品
- 技术风险：系统稳定性问题

**应对措施**：
- 增长风险：多渠道推广，优化获客策略
- 竞争风险：强化竞争优势，快速迭代
- 技术风险：加强测试，建立监控

---

### 90 天计划（规模化阶段）

**目标**：规模化，商业化

**核心原则**：
- 规模：规模化用户，扩大市场
- 商业：开始商业化，验证盈利模式
- 生态：建立生态，增强护城河

**关键活动**：
1. **产品扩展**
   - 上线移动应用
   - 实现 AI 推荐模型（高级版）
   - 增加高级功能

2. **商业运营**
   - 开始商业化运营
   - 建立商业模式
   - 收入验证

3. **规模化增长**
   - 多渠道推广
   - 获得 5000 用户
   - 建立合作伙伴关系

4. **生态建设**
   - 建立开发者生态
   - 建立内容生态
   - 建立品牌生态

**关键指标**：
- 用户数：> 5000
- 收入：> 10 万
- 用户满意度：> 4.5/5
- 商业模式验证：初步验证成功

**里程碑**：
- Day 70：上线移动应用
- Day 80：开始商业化运营
- Day 85：达到 3000 用户
- Day 90：达到 5000 用户，输出商业化报告

**资源需求**：
- 开发人员：5 人
- 运营人员：3 人
- 市场人员：2 人
- 商业人员：1 人
- 推广预算：50 万元

**风险识别**：
- 商业风险：商业模式验证失败
- 市场风险：市场竞争加剧
- 资源风险：资源不足

**应对措施**：
- 商业风险：灵活调整商业模式，多模式并行
- 市场风险：强化竞争优势，快速响应
- 资源风险：合理规划资源，寻求外部支持

## 🎯 质量标准

### 计划完整性

| 指标 | 标准 |
|------|------|
| 目标明确 | 每个阶段都有明确的目标 |
| 活动完整 | 每个阶段的关键活动都完整 |
| 指标明确 | 每个阶段的关键指标都明确 |
| 里程碑清晰 | 每个阶段的里程碑都清晰 |

### 计划可行性

| 指标 | 标准 |
|------|------|
| 时间合理 | 每个阶段的时间安排合理 |
| 资源可获得 | 每个阶段的资源可获得 |
| 可执行性强 | 计划可执行，不是空谈 |
| 风险可控 | 风险识别充分，应对措施明确 |

### 计划逻辑性

| 指标 | 标准 |
|------|------|
| 阶段衔接 | 各阶段之间衔接合理 |
| 目标递进 | 各阶段目标递进，符合逻辑 |
| 资源匹配 | 资源需求与目标匹配 |
| 指标一致 | 各阶段指标一致，相互支持 |
