# POV Builder Skill

这是Eureka! AI价值创新系统的第二个Skill，负责构建用户POV（Point of View）。

## 目录结构

```
pov_builder/
├── SKILL.md              # Skill定义文件
├── README.md            # 本文件
├── references/          # 参考文档
│   └── pov_guide.md    # POV构建指南
└── examples/            # 示例输出
    ├── example_1.json   # 示例1：工作回顾承诺机制
    └── example_2.json   # 示例2：新零售用户体验
```

## 核心功能

将项目简报中的以下信息整合为清晰的用户视角陈述：

1. **用户画像**
   - 用户角色和背景
   - 用户特征和行为模式
   - 用户的工作/生活场景

2. **场景挑战**
   - 使用场景描述
   - 障碍和限制
   - 约束条件

3. **用户痛点**
   - 旅程触点的具体痛点
   - 严重程度和发生频率

4. **用户需求**
   - 显性需求（明确表达的需求）
   - 隐性需求（未表达但真实需要的需求）
   - 情感需求（感受、动机）

5. **POV陈述**
   - 行动导向/洞察导向/情感导向
   - 关键洞察

6. **成功标准**
   - 体验改善描述
   - 价值指标
   - 满意度维度

7. **用户探索发现**
   - 探索方法
   - 关键发现
   - 意外发现

## 使用方式

### 方式1: 自动执行（推荐）
由主调度器自动调用，基于 `build_project_brief` 的输出生成POV。

### 方式2: 交互式GUI输入 ⭐（用户自定义）
当需要用户手动输入或修正四个关键信息时，使用交互式GUI界面：

**步骤**:
1. 在浏览器中打开GUI界面：
   ```bash
   open eureka_value_inovation/.workbuddy/skills/pov_builder/templates/pov_gui.html
   ```

2. **填写四个关键信息**:
   - **1. 用户画像**: 用户角色、背景、特征标签
   - **2. 场景挑战**: 使用场景、障碍、约束条件
   - **3. 期望目标**: 显性需求、隐性需求、情感需求
   - **4. 用户探索发现**: 探索方法、关键发现、意外发现

3. **生成POV**: 点击"🚀 生成POV"按钮

4. **查看输出**: JSON格式和POV卡片同时显示
5. **复制输出**: 将生成的JSON输出保存到项目目录

### POV卡片格式

POV卡片按照以下标准格式生成：

**(用户) 在 （场景下） 面对 （挑战/痛点），期望达成（目标/结果），因为 （洞察出来的需求）**

**示例**:
```
中层管理者Alice 在 周度工作回顾会议 场景下
面对 团队成员只列举待办，不承诺具体目标
期望达成 在工作回顾中明确可承诺的目标，以提升目标清晰度和责任追踪能力
因为 Alice的深层需求不是'更好的工具'，而是'建立承诺文化'
```

**特性**:
- ✅ 视觉化展示，易于理解
- ✅ 渐变色彩，美观大方
- ✅ 关键信息高亮显示
- ✅ 包含洞察，激发创新

**GUI特性**:
- ✅ 简洁设计，结构化输入
- ✅ 标签系统（按回车添加标签）
- ✅ 实时验证和错误提示
- ✅ 自动生成JSON输出
- ✅ 美观的界面和动画效果

### 方式3: WorkBuddy对话调用


## POV陈述的三种格式

### 1. 行动导向
"作为[用户角色]，我需要[具体需求]，以便[价值/目标]"

### 2. 洞察导向
"[用户角色]在[场景]中，遇到了[痛点]，这意味着[深层需求]"

### 3. 情感导向
"[用户角色]感到[情感]因为[挑战]，他们渴望[期望]"

## 与系统的集成

- **上游**: `build_project_brief` - 提供用户画像、场景挑战、期望目标
- **下游**:
  - `find_insight`: 使用user_needs和pain_points进行FIND洞察
  - `roleplay_stakeholder`: 使用user_persona进行利益相关方模拟
  - `hmw_reframer`: 使用pov_statement构建HMW机遇

## 关键原则

1. **用户中心**: 所有陈述必须从用户视角出发
2. **深度洞察**: 不仅要看表面需求，要挖掘深层动机和情感需求
3. **场景化**: 痛点和需求必须在具体场景中描述
4. **可验证**: POV陈述和成功标准必须可观察、可测量
5. **情感共鸣**: 捕捉用户的真实感受，建立情感连接
