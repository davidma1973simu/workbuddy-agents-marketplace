# POV Builder Skill

**Skill Name**: `pov_builder`

**Description**: 构建用户POV（Point of View），将项目简报中的用户画像、场景挑战、期望目标和用户探索发现，整合为清晰的用户视角陈述，明确用户的真实需求和痛点。

## 触发场景

当以下条件满足时触发：
- 已经完成 `build_project_brief` Skill，生成了项目简报
- 需要从用户视角理解问题和需求
- 主调度器在Reveal阶段调用此Skill
- 用户需要手动输入或修正四个关键信息

## 使用方式

### 方式1: 自动执行（推荐）
由主调度器自动调用，基于 `build_project_brief` 的输出生成POV。

### 方式2: 交互式GUI输入（用户自定义）
当需要用户手动输入或修正四个关键信息时，使用交互式GUI界面：

1. **打开GUI界面**:
   ```bash

   open /Users/davidma/WorkBuddy/Claw/eureka_value_inovation/.workbuddy/skills/pov_builder/templates/pov_gui.html
   ```

2. **填写四个关键信息**:
   - **1. 用户画像**: 用户角色、背景、特征标签
   - **2. 场景挑战**: 使用场景、障碍、约束条件
   - **3. 期望目标**: 显性需求、隐性需求、情感需求
   - **4. 用户探索发现**: 探索方法、关键发现、意外发现

3. **生成POV**: 点击"🚀 生成POV"按钮，系统自动生成JSON输出

4. **复制输出**: 将生成的JSON输出复制回工作区或保存到项目目录

### 方式3: WorkBuddy对话调用

## 工作流程

### 步骤 1: 提取用户画像（User Persona）
从 `build_project_brief` 输出中提取：
- 用户角色和背景
- 用户特征和行为模式
- 用户的工作/生活场景

### 步骤 2: 分析场景挑战（Context Challenge）
整合以下信息：
- 核心设计挑战（core_challenge）
- 背景案例（background）
- 用户旅程中的障碍和限制

### 步骤 3: 识别用户痛点（Pain Points）
基于用户画像和场景，识别：
- 当前体验中的具体痛点
- 用户在旅程触点遇到的困难
- 未被满足的需求和期望

### 步骤 4: 深化用户需求（Deep Needs）
通过用户探索和洞察，识别：
- 表层需求（用户明确表达的需求）
- 深层需求（用户未明确表达但真实需要的需求）
- 情感和社交需求（用户的感受、动机）

### 步骤 5: 构建用户POV陈述（POV Statement）
使用标准格式整合所有信息：

**格式1：行动导向**
"作为[用户角色]，我需要[具体需求]，以便[价值/目标]"

**格式2：洞察导向**
"[用户角色]在[场景]中，遇到了[痛点]，这意味着[深层需求]"

**格式3：情感导向**
"[用户角色]感到[情感]因为[挑战]，他们渴望[期望]"

### 步骤 6: 生成POV卡片（POV Card）
按照以下格式生成POV卡片：

**格式**: (用户) 在 （场景下） 面对 （挑战/痛点），期望达成（目标/结果），因为 （洞察出来的需求）

**示例**:
```
中层管理者Alice 在 周度工作回顾会议 场景下
面对 团队成员只列举待办，不承诺具体目标
期望达成 在工作回顾中明确可承诺的目标，以提升目标清晰度和责任追踪能力
因为 Alice的深层需求不是'更好的工具'，而是'建立承诺文化'——她希望团队能够真正对自己的工作负责，形成可追踪、可衡量的目标意识
```

### 步骤 7: 定义成功标准
定义用户视角的成功标准：
- 用户期望的体验改善
- 用户价值实现的具体指标
- 用户满意度的关键维度

### POV卡片格式

POV卡片遵循以下标准格式：

**(用户) 在 （场景下） 面对 （挑战/痛点），期望达成（目标/结果），因为 （洞察出来的需求）**

- **用户**: 用户角色或身份
- **场景下**: 具体的使用场景或工作/生活情境
- **挑战/痛点**: 用户面临的主要障碍或困难
- **目标/结果**: 用户期望达成的目标或获得的结果
- **洞察出来的需求**: 从隐性需求、情感需求或关键发现中提取的深层洞察

**示例**:
```
中层管理者Alice 在 周度工作回顾会议 场景下
面对 团队成员只列举待办，不承诺具体目标
期望达成 在工作回顾中明确可承诺的目标，以提升目标清晰度和责任追踪能力
因为 Alice的深层需求不是'更好的工具'，而是'建立承诺文化'——她希望团队能够真正对自己的工作负责，形成可追踪、可衡量的目标意识
```

## 关键原则

1. **用户中心**: 所有陈述必须从用户视角出发，避免第三方视角
2. **深度洞察**: 不仅要看表面需求，要挖掘深层动机和情感需求
3. **场景化**: 痛点和需求必须在具体场景中描述，增强真实感
4. **可验证**: POV陈述和成功标准必须可观察、可测量
5. **情感共鸣**: 捕捉用户的真实感受，建立情感连接

## 错误处理

### P1 错误（必须处理）
- 输入数据缺失用户画像 → 返回错误，要求用户提供用户信息
- 无法识别具体痛点 → 使用通用占位符并标记"待深入探索"
- 无法构建有效POV陈述 → 返回错误，要求澄清用户场景

### P2 错误（可容忍）
- 用户探索数据不足 → 使用典型场景推断，标记"待验证"
- 成功标准难以量化 → 使用定性描述，标记"待细化"
