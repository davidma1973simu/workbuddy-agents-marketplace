# POV Builder GUI 使用指南

## 概述

POV Builder提供了一个交互式GUI界面，让用户能够结构化地输入四个关键信息，快速生成用户POV。

## 四个关键信息

### 1. 用户画像
**目的**: 定义用户的角色和特征

**必填字段**:
- **用户角色**: 用户的职业或身份（例如：中层管理者、都市白领消费者）
- **用户背景**: 描述用户的工作/生活背景、环境和特点（2-3句话）

**可选字段**:
- **用户特征（标签）**: 用户的特征和行为模式
  - 输入方式：输入标签后按回车添加
  - 示例：`注重效率` + 回车、`时间紧张` + 回车
  - 删除标签：点击标签上的 × 号

**示例**:
```
用户角色: 中层管理者
用户背景: 负责5人团队的周度工作回顾和目标管理，每周五下午召开回顾会议，
        使用简报工具总结工作。注重效率，但当前缺乏有效的目标追踪机制
用户特征: 注重效率、时间紧张、习惯使用简报、对承诺机制缺乏敏感度
```

---

### 2. 场景挑战
**目的**: 定义用户遇到问题和挑战的场景

**必填字段**:
- **使用场景**: 描述用户在什么场景下遇到问题
- **主要障碍**: 列出用户遇到的主要障碍或困难

**可选字段**:
- **约束条件**: 时间、资源、技术等方面的限制

**示例**:
```
使用场景: 周度工作回顾会议场景，Alice需要收集团队成员的工作汇报，
         整理成总结，在会上分享，并追踪执行进展
主要障碍: 团队成员只列举待办，不承诺结果
          目标模糊，无法量化进展
          缺乏追踪机制，承诺易被遗忘
约束条件: 时间限制（周五下午1小时）
          工具限制（现有简报工具不支持承诺设定）
          文化限制（团队缺乏承诺意识）
```

---

### 3. 期望目标
**目的**: 定义用户的需求和期望

**必填字段**:
- **显性需求**: 用户明确表达的需求
  - 输入方式：每行一个需求

**可选字段**:
- **隐性需求**: 用户未明确表达但真实需要的需求（每行一个）
- **情感需求**: 用户的感受、动机和情感状态（每行一个）

**示例**:
```
显性需求:
需要清晰的目标定义工具
需要简洁的工作回顾模板
需要目标追踪和反馈系统
需要不增加额外工作负担

隐性需求:
渴望提升团队执行力
希望获得管理成就感
需要展示团队价值给上级

情感需求:
焦虑：担心团队目标不清晰影响业绩
挫败：承诺无法落实带来的无力感
压力：上级对执行效率的要求
期待：看到团队成长和成果
```

---

### 4. 用户探索发现
**目的**: 记录从用户探索中获得的关键发现

**必填字段**:
- **探索方法**: 获取用户洞察的方法
  - 例如：深度访谈、用户调研、观察、旅程地图
- **关键发现**: 从探索中获得的关键发现（每行一个）

**可选字段**:
- **意外发现**: 探索中的意外发现或反直觉的洞察（每行一个）

**示例**:
```
探索方法: 深度访谈（与Alice和5名团队成员）+ 旅程地图绘制 + 观察（参与2次回顾会议）

关键发现:
团队成员不承诺的根本原因是害怕失败和责任
Alice使用简报是因为习惯，而非最佳选择
现有工具不支持承诺设定和追踪，需要简单易用的替代方案
团队缺乏对承诺的仪式感，承诺没有严肃性

意外发现:
Alice其实知道问题所在，但不知道如何改变，需要外部方法支持
团队成员愿意承诺，但需要明确的模板和引导，而非强制要求
承诺的核心不是'控制'，而是'可见性'和'反馈'
```

## 生成POV

1. **填写完成后**，点击页面底部的"🚀 生成POV"按钮

2. **系统验证**:
   - 检查所有必填字段是否已填写
   - 如果有缺失，显示错误提示（红色）
   - 如果全部填写，显示成功提示（绿色）

3. **自动生成**:
   - 系统自动构建JSON格式的POV输出
   - 生成时间戳和项目ID
   - 整合四个关键信息

4. **查看输出**:
   - 输出显示在页面底部的"📊 POV输出"区域
   - 包含两部分：
     - **JSON格式输出**: 完整的结构化数据
     - **POV卡片**: 可视化的POV展示（渐变紫色背景）
   - 可以复制粘贴

## POV卡片

POV卡片是可视化的POV展示，格式为：

**(用户) 在 （场景下） 面对 （挑战/痛点），期望达成（目标/结果），因为 （洞察出来的需求）**

**示例**:
```
中层管理者Alice 在 周度工作回顾会议 场景下
面对 团队成员只列举待办，不承诺具体目标
期望达成 在工作回顾中明确可承诺的目标，以提升目标清晰度和责任追踪能力
因为 Alice的深层需求不是'更好的工具'，而是'建立承诺文化'
```

**卡片特性**:
- 🎯 渐变紫色背景，美观大方
- ✨ 关键信息高亮显示（黄色）
- 💡 洞察单独展示在底部
- 🎨 动画效果，滑入显示

生成JSON后，可以：

1. **保存到文件**:
   ```bash

   vi_20260322_001/01_pov_builder.json
   ```

2. **集成到工作流**:
   - 将JSON传递给下游Skill（如 `find_insight`、`hmw_reframer`）

   - 如果需要修改，可以重新打开GUI

## 技巧和建议

### 标签输入
- 按回车键添加标签，不要按空格
- 点击 × 删除标签
- 标签应该简洁明了（2-4个字）

### 多行输入
- 对于需要多个选项的字段（如需求、发现），每行输入一个
- 系统会自动按行分割成数组

### 必填 vs 可选
- 必填字段有 * 标记
- 可选字段可以留空
- 建议尽可能填写所有字段，以获得完整的POV

### 数据质量
- 使用具体、可观察的描述
- 避免模糊的表述（如"不好"、"很差"）
- 尽量使用数据和事实支撑

## 常见问题

**Q: 如何删除已添加的标签？**
A: 点击标签上的 × 号即可删除。

**Q: 必填字段可以留空吗？**
A: 不可以。点击"生成POV"时会提示错误。

**Q: 生成的JSON可以直接使用吗？**
A: 可以。JSON格式符合系统规范，可以直接用于下游Skill。

**Q: 可以修改已生成的POV吗？**
A: 可以。重新打开GUI修改后重新生成，或直接编辑JSON文件。

**Q: GUI支持移动设备吗？**
A: 是的，GUI是响应式设计，支持桌面和移动设备。
