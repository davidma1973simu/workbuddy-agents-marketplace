# Solution_Build - 方案构建师

## 📋 基本信息

- **Skill ID**: `Solution_Build`
- **Skill 名称**: 方案构建师
- **所属 Agent**: Shape Specialist（架构师）
- **版本**: v1.0.0
- **类型**: 构建类

---

## 🎯 功能定义

**核心功能**：将压力测试的结果和回应整合为完整的概念方案，明确功能和特性，设计 AHA 价值

**构建目的**：
- 提供完整的概念方案
- 明确功能和特性
- 设计 AHA 价值
- 为后续原型设计提供基础

---

## 🏗️ 构建内容

### 1. 概念名称

**要求**：
- 简洁有力（2-4 个单词）
- 易于记忆和传播
- 体现核心价值
- 避免技术术语

**示例**：
- ❌ "基于 AI 的个性化产品推荐和决策支持系统"
- ✅ "ShopMate AI"
- ✅ "购物智能助手"

---

### 2. 核心价值（AHA 价值设计）

**AHA 价值声明**：
- 一句话说明用户获得的价值
- 清晰、具体、可衡量
- 包含价值维度（时间、成本、体验等）

**格式**：
```
[动词] + [用户获得的价值] + [量化指标/时间/场景]
```

**示例**：
- "让购物决策变得简单、快速、可靠"
- "在 5 分钟内找到最适合自己的产品"
- "节省 80% 的购物时间，提高 90% 的满意度"

---

### 3. 核心功能（3-5 个）

**要求**：
- 覆盖主要痛点
- 功能清晰明确
- 相互关联，形成整体
- 每个功能都有价值主张

**格式**：
```yaml
功能 1:
  功能名称: "[简洁名称]"
  功能描述: "[1-2 句话描述]"
  价值主张: "[用户获得的价值]"
  优先级: "[高/中/低]"

功能 2:
  功能名称: "[简洁名称]"
  功能描述: "[1-2 句话描述]"
  价值主张: "[用户获得的价值]"
  优先级: "[高/中/低]"
```

**示例**：
```yaml
功能 1:
  功能名称: "智能问答"
  功能描述: "用户可以用自然语言提问，AI 给出专业建议和产品推荐"
  价值主张: "无需学习，像和朋友聊天一样简单"
  优先级: "高"

功能 2:
  功能名称: "个性化推荐"
  功能描述: "基于用户画像和偏好，推荐最适合的产品"
  价值主张: "推荐更精准，节省时间"
  优先级: "高"

功能 3:
  功能名称: "对比分析"
  功能描述: "自动对比多个产品的优缺点，帮助用户做出决策"
  价值主张: "全面了解，不遗漏关键信息"
  优先级: "中"

功能 4:
  功能名称: "购买决策"
  功能描述: "综合分析后，给出最终的购买建议"
  价值主张: "决策更放心，减少后顾之忧"
  优先级: "高"
```

---

### 4. 关键特性

**要求**：
- 每个功能对应 2-3 个关键特性
- 特性具体可衡量
- 体现差异化优势
- 支持功能价值主张

**格式**：
```yaml
功能 1:
  特性 1: "[特性描述]"
  特性 2: "[特性描述]"
  特性 3: "[特性描述]"

功能 2:
  特性 1: "[特性描述]"
  特性 2: "[特性描述]"
  特性 3: "[特性描述]"
```

**示例**：
```yaml
智能问答:
  特性 1: "自然语言理解，支持口语化表达"
  特性 2: "30 秒内响应，快速高效"
  特性 3: "多轮对话，可以追问和澄清"

个性化推荐:
  特性 1: "基于用户历史行为和偏好"
  特性 2: "持续学习，越来越智能"
  特性 3: "推荐理由透明，让用户了解为什么推荐"

对比分析:
  特性 1: "自动提取产品关键参数和特性"
  特性 2: "可视化对比表格，一目了然"
  特性 3: "提供优缺点总结和建议"

购买决策:
  特性 1: "综合多维度分析（价格、品质、口碑等）"
  特性 2: "给出明确的购买建议和理由"
  特性 3: "提供替代方案和注意事项"
```

### 5. 技术架构（高层）

**要求**：
- 高层架构，不涉及具体技术细节
- 说明主要技术组件和关系
- 突出技术可行性
- 考虑扩展性和稳定性

**格式**：
```yaml
技术架构:
  前端:
    - "[组件1]"
    - "[组件2]"

  后端:
    - "[组件1]"
    - "[组件2]"

  AI 模型:
    - "[模型1]"
    - "[模型2]"

  数据层:
    - "[组件1]"
    - "[组件2]"

  基础设施:
    - "[服务1]"
    - "[服务2]"
```

**示例**：
```yaml
技术架构:
  前端:
    - "Web 应用（React）"
    - "移动应用（Flutter）"

  后端:
    - "API 网关"
    - "业务逻辑服务"
    - "推荐引擎"

  AI 模型:
    - "自然语言理解模型（NLU）"
    - "推荐算法模型"
    - "用户画像模型"

  数据层:
    - "产品数据库"
    - "用户数据库"
    - "行为日志数据库"

  基础设施:
    - "云服务（阿里云/腾讯云）"
    - "弹性伸缩"
    - "监控和日志"
```

### 6. 商业逻辑

**要求**：
- 说明商业模式
- 说明盈利方式
- 说明成本结构
- 说明增长路径

**格式**：
```yaml
商业模式:
  模式: "[B2B/B2C/B2B2C 等]"
  价值主张: "[为谁提供什么价值]"

盈利方式:
  方式 1:
    描述: "[如何赚钱]"
    定价: "[定价策略]"

  方式 2:
    描述: "[如何赚钱]"
    定价: "[定价策略]"

成本结构:
  固定成本:
    - "[成本项1]"
    - "[成本项2]"
  可变成本:
    - "[成本项1]"
    - "[成本项2]"

增长路径:
  阶段 1:
    目标: "[目标]"
    策略: "[策略]"

  阶段 2:
    目标: "[目标]"
    策略: "[策略]"
```

**示例**：
```yaml
商业模式:
  模式: "B2B2C"
  价值主张: "为电商平台提供智能推荐服务，提升用户体验和转化率"

盈利方式:
  方式 1:
    描述: "按使用量收费，根据用户访问次数和推荐次数计费"
    定价: "0.01 元/次推荐，月结"

  方式 2:
    描述: "按效果收费，根据用户购买转化率提成"
    定价: "佣金率 2-5%"

成本结构:
  固定成本:
    - "技术开发成本（50 万/年）"
    - "服务器和云服务成本（10 万/年）"
  可变成本:
    - "运营和维护成本（0.001 元/次推荐）"
    - "数据获取和标注成本（5 万/年）"

增长路径:
  阶段 1:
    目标: "验证商业模式，获取 10 个电商平台客户"
    策略: "免费试用 + 低门槛接入"

  阶段 2:
    目标: "扩大市场份额，服务 100 个电商平台客户"
    策略: "口碑传播 + 销售团队"

  阶段 3:
    目标: "成为行业领导者，服务 500+ 电商平台客户"
    策略: "品牌建设 + 生态合作"
```

### 7. 利益方关系

**要求**：
- 明确各利益相关者的角色
- 说明各方的价值交换
- 说明各方的激励机制
- 说明各方的约束条件

**格式**：
```yaml
利益方 1:
  角色: "[角色]"
  价值获得: "[获得的价值]"
  价值提供: "[提供的价值]"
  激励机制: "[激励机制]"
  约束条件: "[约束条件]"

利益方 2:
  角色: "[角色]"
  价值获得: "[获得的价值]"
  价值提供: "[提供的价值]"
  激励机制: "[激励机制]"
  约束条件: "[约束条件]"
```

**示例**：
```yaml
用户:
  角色: "最终使用者"
  价值获得: "节省时间，获得专业建议，做出更好的决策"
  价值提供: "提供使用反馈，帮助优化算法"
  激励机制: "更好的推荐体验，更快的决策速度"
  约束条件: "需要提供一定的个人信息"

商家:
  角色: "产品提供者"
  价值获得: "提高转化率，增加销售"
  价值提供: "提供产品数据和库存信息"
  激励机制: "更高的销售转化，更多的曝光"
  约束条件: "需要接受推荐的公平性"

平台:
  角色: "服务提供者"
  价值获得: "提高用户粘性，增加交易额，获得技术服务费"
  价值提供: "提供 AI 推荐服务"
  激励机制: "技术服务费收入，平台竞争力提升"
  约束条件: "需要保证数据安全和隐私"
```

### 8. 实施路径

**要求**：
- 分阶段实施
- 每个阶段有明确的目标和交付物
- 考虑资源限制和风险
- 有里程碑和验收标准

**格式**：
```yaml
阶段 1:
  名称: "[阶段名称]"
  时间: "[时间周期]"
  目标: "[目标]"
  交付物:
    - "[交付物1]"
    - "[交付物2]"
  风险: "[主要风险]"

阶段 2:
  名称: "[阶段名称]"
  时间: "[时间周期]"
  目标: "[目标]"
  交付物:
    - "[交付物1]"
    - "[交付物2]"
  风险: "[主要风险]"
```

**示例**：
```yaml
阶段 1:
  名称: "MVP 开发"
  时间: "3 个月"
  目标: "开发最小可行产品，验证核心功能"
  交付物:
    - "Web 应用原型"
    - "AI 推荐模型（基础版）"
    - "用户测试报告"
  风险: "技术实现难度超预期，需要调整功能范围"

阶段 2:
  名称: "产品迭代"
  时间: "3 个月"
  目标: "根据用户反馈优化产品，提升算法效果"
  交付物:
    - "正式版产品"
    - "AI 推荐模型（优化版）"
    - "运营方案"
  风险: "用户反馈不佳，需要大幅调整产品方向"

阶段 3:
  名称: "市场推广"
  时间: "6 个月"
  目标: "获取 10 个电商平台客户，验证商业模式"
  交付物:
    - "客户签约 10 个"
    - "运营数据分析报告"
    - "商业验证报告"
  风险: "市场推广效果不佳，客户获取成本高"
```

## 🎯 质量标准

### 概念方案完整性

| 指标 | 标准 |
|------|------|
| 概念名称 | 简洁有力，2-4 个单词 |
| 核心价值 | AHA 价值声明明确，一句话说明价值 |
| 核心功能 | 3-5 个，覆盖主要痛点 |
| 关键特性 | 每个功能 2-3 个特性，具体可衡量 |
| 技术架构 | 高层架构清晰，组件明确 |
| 商业逻辑 | 商业模式清晰，盈利路径明确 |
| 利益方关系 | 各方角色和关系明确 |
| 实施路径 | 分阶段规划，里程碑明确 |

### 概念方案质量

| 指标 | 标准 |
|------|------|
| 概念清晰度 | 概念名称简洁有力，一句话可以解释清楚 |
| 价值明确性 | AHA 价值声明明确，用户获得的价值清晰 |
| 功能完整性 | 核心功能覆盖主要痛点 |
| 特具体现性 | 关键特性具体可衡量，不是模糊描述 |
| 技术可行性 | 技术方案在现有技术基础上可实现 |
| 商业可行性 | 商业模式合理，有清晰的盈利路径 |
| 利益方平衡 | 各利益相关者的诉求得到平衡考虑 |
| 实施可行性 | 实施路径清晰，分阶段可执行 |

## 💡 使用示例

### 输入

```yaml
拷问报告:
  创意名称: "AI 智能购物助手"

  用户维度拷问:
    关键发现:
      - "用户信任是关键，需要提供推荐理由和透明度"
      - "用户体验简单快捷，学习成本低"

  技术维度拷问:
    关键发现:
      - "技术相对成熟，但需要大量数据"
      - "需要持续投入优化算法"

  商业维度拷问:
    关键发现:
      - "商业模式清晰，有盈利路径"
      - "需要建立差异化竞争优势"

  利益方维度拷问:
    关键发现:
      - "各方基本接受，需要强调中立性和公平性"
      - "隐私和数据安全是关键关注点"

  拷问总结:
    主要风险:
      - "用户信任风险：需要提供推荐理由和透明度"
      - "数据质量风险：需要建立数据清洗流程"
      - "竞争风险：需要建立差异化竞争优势"
    关键假设:
      - "数据能够获取且质量足够"
      - "算法效果能够持续优化"
      - "用户愿意接受 AI 推荐"
    优先改进项:
      - "提供推荐理由，增强用户信任"
      - "建立数据质量监控机制"
      - "明确差异化竞争优势"
```

### 输出

```yaml
概念方案:
  概念名称: "ShopMate AI"
  核心价值: "让购物决策变得简单、快速、可靠，在 5 分钟内找到最适合自己的产品"

  核心功能:
```
