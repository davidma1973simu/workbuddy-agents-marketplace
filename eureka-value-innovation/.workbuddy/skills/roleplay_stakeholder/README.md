## 核心功能

在创新项目启动时，通过利益相关方模拟了解各方需求和影响力，使用Buy Features方法达成共识：

1. **识别利益相关方**
   - 决策者（有权决定项目方向）
   - 影响者（对项目有影响力）
   - 执行者（负责实际执行）
   - 受益者（最终获益）
   - 阻碍者（可能阻碍项目）

2. **模拟利益相关方视角**
   - 角色定位和职责
   - 核心关注点
   - 需求和期望

3. **Buy Features方法（需求优先级）**
   - ✅ 最多4个需求
   - ✅ 重要性打分1-5分
   - ✅ 总分12分限制
   - ✅ 强制优先级

4. **影响力评估**
   - 1分：无关
   - 2分：相关
   - 3分：有很大影响力

5. **生成需求优先列表**
   - 按影响力水平分组
   - 按重要性排序
   - 简洁清晰的列表展示

## 使用方式

### 方式1: 自动执行（推荐）
由主调度器自动调用，基于 `build_project_brief` 的输出生成利益相关方分析。

### 方式2: 交互式GUI输入 ⭐（用户自定义）

**步骤**:
1. 在浏览器中打开GUI界面：
   ```bash
   open eureka_value_inovation/.workbuddy/skills/roleplay_stakeholder/templates/stakeholder_gui.html
   ```

2. **填写每个利益相关方信息**:
   - **利益相关方名称**: 姓名或角色名称
   - **角色定位**: 描述其在项目中的角色和职责
   - **核心关注点**: 最关心的问题和目标
   - **Buy Features**: 最多4个需求，每个打分1-5分，总分12分
   - **影响力评估**: 选择1-3分（无关/相关/很大影响）

3. **验证总分**:
   - 每个利益相关方的Buy Features总分必须等于12分
   - 系统会实时验证（绿色=有效，红色=无效）

4. **生成分析**: 点击"🚀 生成利益相关方分析"按钮

5. **查看输出**:
   - JSON格式输出（完整数据）
   - 利益相关方需求优先列表（简洁列表）

**GUI特性**:
- ✅ 多个利益相关方卡片
- ✅ Buy Features实时验证（总分12分）
- ✅ 影响力单选评估
- ✅ 自动生成需求优先列表
- ✅ 简洁清晰的列表展示

### 方式3: WorkBuddy对话调用
```
"使用roleplay_stakeholder Skill分析以下项目的利益相关方：[build_project_brief输出]"
```

## Buy Features方法

### 核心约束

```
✓ 最多4个需求
✓ 重要性打分1-5分
✓ 总分12分
```

### 评分示例

**策略1: 突出关键**
- 需求1: 5分（关键需求）
- 需求2: 4分（高优先级）
- 需求3: 2分
- 需求4: 1分
- 总分: 12分 ✅

**策略2: 均衡分配**
- 需求1: 3分
- 需求2: 3分
- 需求3: 3分
- 需求4: 3分
- 总分: 12分 ✅

**策略3: 两极分化**
- 需求1: 5分
- 需求2: 5分
- 需求3: 1分
- 需求4: 1分
- 总分: 12分 ✅

## 影响力评估

### 1分（无关）
- 对项目几乎没有影响
- 可以忽略其意见而不影响项目进展

### 2分（相关）
- 对项目有一定影响
- 需要考虑其意见

### 3分（有很大影响力）
- 对项目有重大影响
- 必须获得其支持

## 与系统的集成

- **上游**: `build_project_brief` - 提供stakeholders列表
- **下游**:
  - `hmw_reframer`: 使用利益相关方需求构建HMW机遇
  - `idea_distiller`: 使用优先级筛选最佳创意
  - `pitch_composer`: 使用共识分析构建说服性演讲
