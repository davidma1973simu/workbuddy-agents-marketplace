# Roleplay Stakeholder Skill

**Skill Name**: `roleplay_stakeholder`

**Description**: 在创新项目启动时，通过利益相关方模拟了解各方需求和影响力，使用Buy Features方法达成共识。强制限制最多4个需求，每个需求重要性打分1-5分，总分12分，确保利益方对需求给出优先顺序。影响力打分1-3分（1无关/2相关/3很大影响）。最终生成简洁的利益方需求优先列表和影响力水平列表。

## 触发场景

当以下条件满足时触发：
- 已经完成 `build_project_brief` 和 `pov_builder` Skill
- 需要在创新项目启动时了解利益相关方需求和影响力
- 主调度器在Reveal阶段调用此Skill
- 需要为利益相关方分析达成共识

## 工作流程

### 步骤 1: 识别利益相关方
从 `build_project_brief` 的stakeholders列表中提取，或根据项目背景识别：
- 决策者（Decision Makers）：有权决定项目方向和资源分配
- 影响者（Influencers）：对项目有影响力，但无决策权
- 执行者（Executors）：负责项目实际执行
- 受益者（Beneficiaries）：最终从项目中获益
- 阻碍者（Blockers）：可能阻碍项目进展

### 步骤 2: 模拟利益相关方视角
针对每个利益相关方，模拟其视角：
- 角色定位：在项目中的角色和职责
- 核心关注点：最关心的问题和目标
- 需求和期望：对项目的具体需求
- 影响力程度：对项目的影响力（1-3分）

### 步骤 3: 应用Buy Features方法（需求优先级）
对每个利益相关方的需求进行Buy Features分析：

**约束规则**：
- **最多4个需求**：每个利益相关方最多列出4个关键需求
- **重要性打分1-5分**：每个需求的重要性评分
- **总分12分限制**：所有需求的重要性总分必须等于12分
- **强制优先级**：分数分配反映需求的优先级顺序

**重要性打分参考**：
- **1分**: 基础需求，不可或缺
- **2分**: 重要需求，影响较大
- **3分**: 关键需求，核心功能
- **4分**: 高优先级需求，关键成功因素
- **5分**: 顶级需求，项目成败的关键

**示例分配**:
- 需求1: 5分（最高优先）
- 需求2: 3分
- 需求3: 3分
- 需求4: 1分
- 总分: 12分 ✅

### 步骤 4: 评估影响力水平
对每个利益相关方的影响力进行评估：

**影响力打分**：
- **1分（无关）**: 对项目几乎没有影响，利益相关方的态度对项目成败影响很小
- **2分（相关）**: 对项目有一定影响，利益相关方的支持/反对会影响项目进展
- **3分（有很大影响力）**: 对项目有重大影响，利益相关方的态度决定项目成败

**评估维度**：
- 决策权：是否有权决定项目方向
- 资源控制：是否控制项目所需资源
- 影响范围：影响的项目范围和程度
- 关键性：对项目成功的关键程度

### 步骤 5: 生成需求优先列表
为每个利益相关方生成需求优先列表，包含：
- 需求描述
- 重要性评分（1-5分）
- 优先级（根据分数排序）

### 步骤 6: 生成影响力水平列表
生成利益相关方影响力水平列表，包含：
- 利益相关方角色
- 影响力评分（1-3分）
- 影响力描述（无关/相关/有很大影响力）
- 关键关注点

### 步骤 7: 达成共识
识别利益相关方之间的冲突和共同点，提出共识建议：
- 冲突识别：哪些需求或目标存在冲突
- 共同点识别：哪些需求和目标是一致的
- 共识建议：如何平衡各方利益，达成共识

## Buy Features方法说明

### 核心原则

1. **强制限制**: 最多4个需求，总分12分
2. **优先级明确**: 分数分配反映需求优先级
3. **达成共识**: 通过限制促使利益相关方思考真正重要的需求
4. **可执行**: 优先级指导后续设计和决策

### 评分策略

**策略1: 突出关键**
- 需求1: 5分（关键需求）
- 需求2: 4分（高优先级）
- 需求3: 2分
- 需求4: 1分
- 总分: 12分

**策略2: 均衡分配**
- 需求1: 3分
- 需求2: 3分
- 需求3: 3分
- 需求4: 3分
- 总分: 12分

**策略3: 两极分化**
- 需求1: 5分
- 需求2: 5分
- 需求3: 1分
- 需求4: 1分
- 总分: 12分

## 影响力评估标准

### 1分（无关）
- 对项目几乎没有影响
- 利益相关方的态度对项目成败影响很小
- 可以忽略其意见而不影响项目进展

**特征**:
- 无决策权
- 不控制关键资源
- 影响范围有限
- 可替代性强

### 2分（相关）
- 对项目有一定影响
- 利益相关方的支持/反对会影响项目进展
- 需要考虑其意见

**特征**:
- 有一定决策权
- 控制部分资源
- 影响项目特定环节
- 对项目有中等重要性

### 3分（有很大影响力）
- 对项目有重大影响
- 利益相关方的态度决定项目成败
- 必须获得其支持

**特征**:
- 有重大决策权
- 控制关键资源
- 影响项目整体
- 对项目成功至关重要

## 关键原则

1. **全面性**: 识别所有关键利益相关方，不遗漏重要角色
2. **真实性**: 真实模拟利益相关方视角，避免主观偏见
3. **优先级清晰**: 通过Buy Features方法强制给出明确优先级
4. **影响力准确**: 准确评估各方影响力，识别关键利益相关方
5. **共识导向**: 识别冲突和共同点，寻求平衡和共识

## 错误处理

### P1 错误（必须处理）
- 输入数据缺少利益相关方信息 → 返回错误，要求提供利益相关方列表
- Buy Features总分不等于12分 → 返回错误，要求调整评分
- 影响力打分超出1-3分范围 → 返回错误，要求重新评分

### P2 错误（可容忍）
- 利益相关方需求超过4个 → 截断为前4个，标记"未包含所有需求"
- 某个利益相关方的关键关注点不明确 → 使用推断内容，标记"待确认"

## 与其他Skill的协作

**上游**:
- `build_project_brief`: 提供stakeholders列表和背景信息
- `pov_builder`: 提供user_persona和user_needs，帮助理解利益相关方视角

**下游**:
- `hmw_reframer`: 使用利益相关方需求构建HMW机遇
- `idea_distiller`: 使用优先级筛选最佳创意
- `pitch_composer`: 使用共识分析构建说服性演讲
