# Transform V2.0 修订思考（规划稿 · 未实现）

> 本文件是 **思考/规划**，不是实现。所有改动需在 `transform-v2.0/` 副本上进行，并经你确认后分批落地。
> 硬约束：本轮**不修改主页视觉设计**（色彩/字体/卡片风格/布局语言），内容层级重组须沿用既有设计语言。
> 本轮目标：**优化体验与价值感知，不增加功能**。

---

## 0. 四个核心功能的定位（先对齐，再谈改）

| 功能 | 文件 | 定位 | 时长 | 当前状态 |
|------|------|------|------|----------|
| 每日洞察 | `think.html` | 每天想清楚一件**小**事 | 3–7 min | ✅ 接近目标：一个问题→AI 出 1 个启发问题→整合洞察 |
| 伴我洞察 | `app.html` | 真正解决一个**复杂**问题 | 较长/多轮 | ⚠️ 暴露"归类/洞察/应用"步骤感，需弱化 |
| 每日改变 | `punch.html` | 今天真做一个**小**改变 | 3–5 min | ✅ 已改纯罗列+「开始今日的行为实验」；已有"没做到"面板 |
| 伴我改变 | `act.html` | 解决长期"知道却做不到" | 长周期 | ⚠️ 仍是"21天计划"框架，需转为"行为实验" |

**关键区分**：每日功能 ≠ 简化版伴我。每日是"一次小推进"，伴我是"深度处理"。两者靠"自然升级"连接，不是平级菜单。

---

## 1. 首页与入口层级（P0-01 / P0-04 / P0-12 / P0-15）

### P0-01 首页 = 每日启动器
- **当前**：hero 主 CTA 已指向 `think.html`/`punch.html`（每日优先）；但"今日微行动"widget 直接链 `act.html`（伴我改变），且底部 FAB「成长资产」→认知档案。四个功能在视觉上未明确分"每日 / 伴我"两层。
- **思考**：保留现有卡片视觉，仅重组文案层级：
  - 第一层「今天，我想做什么？」：每日洞察 / 每日改变（现有 hero 卡片即可复用）
  - 第二层「有件重要的事，需要认真处理？」：伴我洞察 / 伴我改变（改用更小号/次级样式的入口，不抢视觉主位）
  - 现有"今日微行动"widget 保留但归到「每日改变」下，不再直接跳伴我。
- **是否碰主页视觉**：仅调文案与入口层级，**不**改配色/卡片样式 → 符合约束。

### P0-04 隐藏方法论（全产品文案核查）
当前仍暴露在用户面前的"方法术语"需替换（app.html 最重）：
- 信息归类 → **把事情说清楚**
- 视角重构 → **换一个角度看看**
- 远应用迁移验证 → **换一个场景试试看**
- 建立行为锚点 → **今天准备怎么做？**
- "第 1 步·归类 / 第 2 步·洞察 / 第 3 步·应用" → 见 P0-06 三阶段
- 方法机制可保留在代码/提示词里，**不**成为界面语言。

### P0-12 主动发现（首页出现"我发现了一个关于你的模式"）
- **前提**：必须有真实用户数据支撑，禁止编造。
- **触发**：当 `trf_archive` / `trf_actions` 积累到阈值（建议：洞察 ≥ 5 条 或 行为实验 ≥ 3 次）才可能出现。
- **形式**：首页顶部一个次级卡片「我发现了一个关于你的模式 →」点击进档案查看。下钻逻辑见 P0-11。

### P0-15 隐藏技术配置
- **当前**：nav 中「设置」→ `app.html?settings=1` 直接暴露 模型品牌 / API Key 给所有用户。
- **思考**：移出主 nav；保留为 MVP 测试入口（如长按 logo 5 次 / 角落三击），普通用户体验只看到"AI 已准备好"。设置面板本身可保留实现，只是入口藏起来。

## 2. 每日功能压缩（P0-02 / P0-03 / P0-14）

### P0-02 每日洞察 3–7 min
- `think.html` 已是：输入真实问题 → AI 整理/挑战（单轮启发问题）→ 用户形成新判断 → 保存洞察。基本达标。
- **待查**：确认没有"多个连续输入框"和"方法解释"长文本；"让知行整合出洞察"按钮文案可保留（已用户友好）。

### P0-03 每日改变 3–5 min
- `punch.html` 当前流程：选触发时刻 → 今日小步骤(纯罗列) → 「开始今日的行为实验」→ 完成/没做到 → 简单反馈。基本达标。
- 复杂行为设计交给伴我改变，每日只负责"今天做一步"。

### P0-14 手机优先
- 原则：一屏一任务（一个问题→回答→下一步），减少长文本、减少滚动、CTA 始终明确。
- **增强项**（非必须）：支持一句话输入 + 语音输入。建议本轮先保证"一屏一任务"结构，语音输入列为可选。

## 3. 每日 → 伴我 自然升级（P0-05）

- **当前**：think 结果页有「把这个洞察变成今天的改变 →」；punch 有"做完了/没做到"。但**没有"这个问题值得认真处理？→ 伴我"的情境化入口**。
- **思考**：每日完成后不只显示"完成"，根据内容判断给出自然延伸：
  - 洞察结果页：「这个问题值得认真处理？**和我一起继续 → 伴我洞察**」
  - 改变失败/反复：「如果你发现自己一直知道该怎么做却还是做不到，**和我一起重新设计 → 伴我改变**」
- 升级必须是**基于当前问题的自然延伸**，不是普通菜单跳转。

---

## 4. 伴我洞察：去步骤感 + 强化远应用（P0-06 / P0-07）

### P0-06 减步骤感 → 三阶段
- **当前**：app.html 显式「第1步·归类 / 第2步·洞察 / 第3步·应用（近/远）」。
- **思考**：用户只看到三个阶段标签：
  - **① 摊开**：把这件事真正摆到桌面上（内部仍跑 事实/判断/信息整理）
  - **② 想透**：找到你可能没看到的东西（内部仍跑 洞察/多视角）
  - **③ 试试看**：把新认知放到真实场景验证（内部仍跑 近应用/远应用/认知沉淀）
- 内部机制不变，只换用户可见的"阶段语言"。

### P0-07 强化远应用
- **当前**：远应用前有「为什么迁移」解释卡（偏教学）。
- **思考**：**少解释，多体验**。直接把认知带入 家庭/朋友/消费/学习/关系/日常生活 等陌生场景，让用户亲历"原来我在不同问题里用的是同一种思维模式"。
- 可保留一句极短引导（如"换一个完全不同的场景，它还能成立吗？"），删除长段原理说明。

## 5. 伴我改变：计划 → 行为实验 + 失败核心化（P0-08 / P0-09 / P0-10）

### P0-08 从"计划"升级为"行为实验"
- **当前**：act.html 是"21天行动计划"叙事（目标→拆解→行动锚定→反馈强化→复盘）。
- **思考**：叙事改为"行为实验"：目标 → 行为拆解 → 真实场景 → 触发点 → 环境 → 行动 → 反馈 → 失败 → 重新设计 → 再次实验。重点从"生成漂亮计划"转向"找到为什么进不了真实生活"。

### P0-09 把"没做到"变成核心反馈
- **当前**：`punch.html` 已有「今天没做到」原因面板（忘了/太麻烦/不想做/没时间）+ AI 不评价 + toast「没做到不是失败，调整一次再试」。✅ 每日改变已具备。
- **缺口**：① `act.html`（伴我改变）缺同等的失败流；② `pickReason()` 目前只记录原因 + 安慰，**未接入"AI 帮助重新设计"分支**。
- **思考**：失败后让用户选原因，AI 不评判，而是给对应重设计：
  - 忘了 → 重新设计触发点
  - 太麻烦 → 缩小行为
  - 没时间 → 改进行发生时间
  - 不想做 / 场景不对 / 其他 → 对应调整
- 形成 失败 → 理解 → 调整 → 再行动 的闭环，而非 失败 → 结束。

### P0-10 身份票从"奖励"变"行为证据"
- **当前**：act.html 显示「身份票 +1 张」「身份票 N 张」，是积分感。
- **思考**：改为"证据"叙事——「今天你又完成了一次行动。这是你第 N 次用行动证明：*我是一个说到做到的人*。」身份 = 长期行为累积出来的证据，不强调 +1 分。

---

## 6. 档案 = 个人成长资产（P0-11 / P0-12）

- **当前**：cognitive/behavior 是历史记录 + 按场景归并 + 回收箱（前几轮已实现）。
- **思考（P0-11）**：系统应从历史数据**主动发现模式**，例如：
  - "最近一个月你形成的 7 条认知，都反复涉及'控制感'"
  - "过去 10 次行为实验中，你最容易在启动阶段失败"
- **思考（P0-12）**：首页在积累足够数据后展示「我发现了一个关于你的模式 →」，点击下钻到档案查看。必须基于真实数据，禁止为"智能感"编造。
- **实现落点**：在 `cognitive.html`/`behavior.html` 顶部新增「模式发现」区，由一段分析函数（读本地 archive/actions）生成，无数据则不显示。

## 7. 数据真实保存（P0-13）

逐项核对（localStorage key 现状）：
- 每日洞察 → `trf_archive`（需确认 think 结果写入）
- 每日改变 → `trf_actions` / `trf_session_draft`
- 伴我洞察 → 需确认 app 结果写入 `trf_archive`
- 伴我改变 → `trf_actions`
- 洞察结果 / 行为结果 → archive / actions
- **失败记录** → punch 有 `logCompletion(false, day, reason, '')`，但需确认失败原因可被档案(P0-11)读取（建议独立 `trf_fail_log` 或并入 actions.logs）
- 身份票 / 复盘 / 用户状态 → act 有 identityStatements；需确认刷新不丢

**验收动作**：每页「保存→离开→返回→继续」走查一遍，刷新页面不丢核心数据。

## 9. 实施顺序建议（最小可验证，分批）

1. **低风险先落**：P0-04（文案去方法化）+ P0-15（隐藏配置入口）→ 纯文案/入口改动
2. **伴我洞察**：P0-06（三阶段去步骤感）+ P0-07（强化远应用）
3. **伴我改变**：P0-08（行为实验叙事）+ P0-09（失败重设计分支，补全 act）+ P0-10（身份证据化）
4. **首页升级**：P0-01（每日启动器分层）+ P0-05（自然升级入口）+ P0-12（主动发现卡片，依赖 P0-11）
5. **档案智能化**：P0-11（模式发现函数）
6. **收尾核查**：P0-13（数据持久化走查）+ P0-14（手机优先逐项检查）

4. **失败重设计**：P0-09 的"AI 帮助重新设计"需要 AI 调用；在 503/限流时是否要有本地降级方案（如固定建议文案）？
