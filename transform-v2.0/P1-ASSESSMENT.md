## 〇、盘点结论：P1 依赖的底座已相当厚实

1. **升级链路已通（P0-05）**：think 结果页升级卡带 `?topic=` → app；punch 结果页升级卡 → act。act 原生支持 `?insight=&scenario=` 上下文带入。
2. **草稿/恢复已有基础**：app.html（伴我洞察）全量会话草稿（`trf_session_draft`，自动保存+启动恢复+完成清除）；act/punch 实验状态持久化于 `trf_actions`（失败 reason 亦在 logs 内）；punch 支持 `?id=` 查看/修订历史实验。
3. **档案能力已强**：认知/行为档案均具备 标签过滤 / 关键字搜索 / 场景归并 / 编辑 / 删除进回收箱 / 恢复 / 30 天自动清理 / 导出 / 本地模式发现（`renderDiscovery`）+ AI 跨时间模式（`renderPatterns`）。
4. **首页是静态入口层**（P0-01 每日启动器两 tier），动态内容目前只有 `homeDiscovery` 模式卡；无「最近洞察/最近改变/继续上次」区。
5. **通知机制不存在**（仅产品内"环境提示/锚点提醒"文案）；**语音**在 think 已有 `#voiceSlot`+`VOICE_ENABLED` 预留，punch 有常量但缺插槽元素。
6. 架构约束：vanilla 单文件 HTML（无构建），跨页共享只能靠外链公共文件（现有 `design-system.css` 先例）或逐页复制。

## 二、需要你拍板的 4 个边界问题

**Q1 · 首页能否加"动态区"？**
P1 中 #3/#8/#9/#15 都落在首页（继续上次 / 最近洞察 / 最近改变 / 直达当天）。P0 约束是"不改视觉只调层级"；P1 若做这些，需在首页加**卡片区块**——会沿用现有设计语言（配色/卡片/字体），不重设计。这算不算破 P0 的界？
- A. 可以，沿用设计语言加动态区（推荐）
- B. 首页保持现状，动态内容放到档案/独立页
- C. 只先加一个最小"继续上次"入口

**Q2 · 语音走哪条路线（#1/#2）？**
纯网页无 App 推送/原生语音。可行路线：Web Speech API（webkitSpeechRecognition）前端识别，中文在 iOS Safari / Chrome 安卓可用，需 https + 麦克风授权；失败/拒权自动降级为文本输入。
- A. Web Speech 渐进增强，think+punch 都做，失败自动降级（推荐）
- B. 本轮仍不做语音，只把插槽补全
- C. 只做 think（每日洞察），punch 后置

**Q3 · 通知做到什么程度（#16）？**
- A. 站内优先：打开首页即见"今天没做完的小事 + 未完成任务"，零打扰（推荐）
- B. 站内 + 浏览器通知（需授权，页面需在线，提醒时效有限）
- C. 本轮不做，维持现状（环境提示/锚点提醒文案）

**Q4 · 推进节奏**
建议三批（每批可验收）：
- **批 1（快速高价值，不碰首页）**：W3 升级带上下文 → W11 归档 → W6 档案时间过滤 → W10 失败趋势
- **批 2（首页动态，依赖 Q1）**：W5 最近动态 → W2 任务连续性 → W4 每日时间线 → W8 周/月回顾
- **批 3（需先验证能力）**：W7 模式总结 AI 化 → W12 AI 一致性审计 → W1 语音 → W9 通知
- 你的选项：A. 按三批推进，每批验收后进下一批（推荐） B. 先做批 1 看效果 C. 先逐条讨论本表再定

## 三、风险与依赖备忘

1. **W1 语音**：识别依赖浏览器能力，必须做成渐进增强（不可用时输入法语音/文本兜底），否则移动端体验不升反降。
2. **W2/W5/W8 时间维度**：archive/actions 均带 `date` 字段（seed 实测），可支撑；跨天/改日期需注意时区与"今天"边界。
3. **W7 模式总结**：AI 只做"表述润色"，统计必须来自本地真实数据；AI 不可用回落本地模板——沿用 P0-09 降级先例。
4. **W11 归档**：新增标志位需兼容旧数据（无字段=未归档）；discovery/统计/回收箱交互要排除已归档项，避免数字错乱。
5. **W12 一致性**：vanilla 无构建，共享原则建议先落"原则文档+逐页审计"，而非强抽模块，控制改动面。
6. **中英流程变更**：每项先中文实现并自测；**全部完成后统一做英文镜像**，届时按 P0 的逐页映射方法一次同步。
