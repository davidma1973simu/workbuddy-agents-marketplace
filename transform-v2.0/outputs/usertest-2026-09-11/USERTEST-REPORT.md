## 三、核心发现：三个 P0 级"新用户死亡点"

**结论先行：产品对"未配置 API Key 的新用户"在两条主链路的起点都不可用。**

### P0-1 · think.html：30 秒开始 = 30 秒死亡
- 小周写下 55 字真实痛点（"担心被 AI 替代想转型……"），点「开始想清楚 →」
- 仅弹 toast「请先在设置里配置 API Key 再开始」，页面无任何后续
- 代码证据：`startThink()` 无 Key 直接 return；全文件 0 处降级/模板（"本地/降级/fallback" 均 0 次）
- **违反产品自己的 AI 降级铁律**（P0-09 先例：AI 不可用一律回落本地固定模板）
- 用户付出（写痛点）与回报（拒绝）严重不对等 → 价值获得感为负

### P0-2 · app.html：无 Key 直接 JS 崩溃 + 错误暴露给用户
- 点「AI 帮我理一理」→ toast 显示 `Cannot read properties of null (reading 'split')`
- 根因：`aiCall()` 无 Key 返回 null → `parseGroupsFromText(null)` 崩溃 → `catch(e){ toast(e.message) }` 把内部错误给用户
- 且「摊开」步骤全部动作（提取信息点/评估来源/分组）均 AI 依赖，**无手动分组路径**
- 点「去想透 →」被弹到 AI 设置面板（设置墙）

### P0-3 · punch.html：创建主按钮只提示不降级
- 无 Key 下点「开始改变 →」→ 仅 toast「AI 还没连接……入口在上方提示里」，流程不动
- 提示条（amber「去连接 AI →」）做得好，但**点主按钮后用户无事可做**——只有提示没有路径

### 对照：执行与档案侧（不依赖 AI）体验完整 ✅
- punch A 态：「正在改变」上下文行 + 第 N 天·连续 X + 本周/累计 + 行为卡 + 双按钮
- 打卡 B 态：「🎉 第 3 天做到了！本周第 3 次·累计 3 天·连续 3 天在锚点做到」+ 身份见证句「你正在成为『懂 AI 的运营专家』的人」+「今天闭环·明天见」
- 行为档案：身份卡（已投 1 票）+ 统计条 + 「7 天实验·已完成 3/7」
- 备份恢复面板：下载/恢复双动作 + 合并/覆盖 + 自动快照

## 六、PMF 建议

### 结论：**暂不宜直接开测真实用户。先修三个 P0（约 1-2 天），再开测。**

理由：不修就测，测试者卡在"没配 Key 用不了"，你收集到的反馈将全是"用不了"，而不是"好不好用"——测试数据全部失效。三个 P0 都是纯本地降级（模板出题/手动分组/模板拆解），不需要任何后端。

### 修复清单（开测前置）
1. **P0-1** think：无 Key 时回落本地启发式问题模板（按主题关键词选 3-5 个固定好问题），toast 改为「未连接 AI，先用通用问题开始 →」
2. **P0-2** app：aiCall 返回 null 时走本地分组（按 source 字段分组即可：事实/听闻/猜测/观察 天然成类）；`toast(e.message)` 一律改为友好文案，永不暴露原始错误
3. **P0-3** punch：无 Key 时主按钮走本地拆解模板（目标 → 7 天通用微行动模板 + 让用户手改第一天），而不是 return
4. **P1 顺手**：删 think 底部孤链接；首页「成长资产」按钮改为「档案」或并入顶栏

### 开测方案（修复后）
- **人数与构成**：3-5 名 MRD P0 用户（知识焦虑 × 转型重叠），至少 2 名完全零引导裸测（只给网址），其余给场景任务
- **任务脚本**："你担心被 AI 替代想转型——用这个产品把这事想清楚，并开始第一个行动"（不给任何操作教程）
- **观测指标**：
  1. 洞察闭环完成率（think/app 走到「沉淀」的比例）——目标 ≥ 60%
  2. 洞察 → 行为 handoff 转化率（从洞察跳到创建实验）——目标 ≥ 40%
  3. 第 3 天打卡留存（个人进步 AHA 的代理）——目标 ≥ 50%
  4. AHA 三问访谈：哪个瞬间你"啊哈"了？（对照顿悟/高光/进步三个预设）
- **PMF 判据**（Sean Ellis 变体）：如果明天起不能用这个产品，你会？很失望 ≥ 40% → 继续 加深；< 40% → 先改价值主张再放量
- **北极星代理**：7 天实验毕业率 + 替代率问卷（旧行为被新行为替换的自评）

### 后端/登录
维持既有结论：**测试期不需要**。全部数据本地 + 备份恢复已闭环。当出现教练要看学员数据（C→B）或代管 AI Key 的商业化需求时再上。

### 7.2 带 Key 才暴露的 2 个真 bug（已修复）

**BUG-A · 推荐场景 JSON 解析失败（P1，影响核心价值）**
- 现象：带 Key 时仍弹「Transform 推荐未能返回有效格式，已用本地生成」→ 用户拿到通用模板卡
- 根因：DeepSeek 把 3 个标题返回成**每行一个独立数组**（`["a"]\n["b"]\n["c"]`），而 `parseTitleList` 用贪婪正则 `\[[\s\S]*\]` 整体匹配 → `JSON.parse` 必然失败
- 关键损失：被抓到的原始返回质量**极高**（「用 AI 把周报初稿从 2 小时压到 10 分钟」——正是用户自己的周报案例），却被解析器整批丢弃
- 修复：`parseTitleList` 增加兼容路径——逐段解析 `\[[^\[\]]*\]` 后合并，主路径（单数组）不变
- 复测：修复后无降级提示，拿到真 AI 个性化标题 ✅

**BUG-B · `unlockFarApp is not defined`（P1，报错到用户界面）**
- 现象：近应用 AI 反馈成功后，页面 toast「评价失败：unlockFarApp is not defined」
- 根因：`aiAppFeedback` 回调里两处调用 `unlockFarApp()`，但该函数**从未定义**（应为"近应用完成后自动展开远应用区"）
- 修复：补上定义（幂等：已展开则不重复切换）
- 复测：函数存在、调用无错、远应用区正确展开 ✅

### 7.5 修订后的 PMF 建议

**结论：可以开测真实用户（3-5 名 P0 画像），带 Key 使用。**

- 前置：引导用户配好 Key（首启向导中加"连接 AI"一步，附 DeepSeek 申请链接）——这是唯一的前置摩擦
- 指标不变：洞察闭环完成率 ≥60%、洞察→行为转化 ≥40%、第 3 天留存 ≥50%、Sean Ellis 变体 ≥40%
- 观察重点：AI 产出被"接受/改写/跳过"的比例——改写率高说明 AI 只是草稿，价值仍成立；跳过率高说明未命中
- 建议顺手修的小项（不阻塞开测）：
  1. think 主按钮配色统一为深绿 #0E6B50
  2. 应用步"确认 →"后的阶段切换反馈更明确（当前易被误认为"弹回上一步"）
  3. AI 解析类函数统一加固（本次 BUG-A 说明"严格 JSON"约定在真实模型上不可靠，建议所有 parse* 都加兼容路径）
