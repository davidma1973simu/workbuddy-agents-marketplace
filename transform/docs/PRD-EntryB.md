## 一、为什么现在做入口 B

入口 A 让用户「想清楚了」，产出了洞察、应用计划和支持资源——**然后就没有然后了**。

这恰好是 MRD §3.2 我们批判竞品的那条罪状：**「洞察后无行动」**。不做入口 B，Transform 就只是「又一个更好的反思工具」，认知-行为闭环的差异化叙事不成立。

**入口 B 要解决的唯一问题**：让用户在**看完洞察的 30 秒内**，真的做出第一个动作。

---

## 二、设计原则（与入口 A 的分工）

| | 入口 A「帮我清楚」 | 入口 B「帮我改变」 |
|---|---|---|
| 解决 | 想不明白 | 想明白了但动不了 |
| 时长 | 一次专注（12-20 分钟） | **30 秒**（单次执行） |
| 节奏 | 单次深度会话 | **持续、低频次、日常化** |
| 产出 | 洞察 + 应用计划 | 已完成的行动 + 身份票 |
| AI 角色 | 追问、照镜子 | **降难度、找锚点、诊断卡点** |
| 情绪 | 澄清的松弛感 | 完成的确定感 |

**四条铁律：**

1. **小到不可能失败**：任何微行动必须 30 秒内可完成，否则强制再拆
2. **不加动机，只降难度**：用户没做到时，永不说「加油/你要坚持」，只问「要不要再小一点 / 换个时机」
3. **完成即庆祝**：每次完成立刻给即时正反馈（福格：情绪创造习惯，不是重复创造习惯）
4. **每次完成 = 给身份投一票**：直接复用入口 A 已有的身份投票机制，两个入口在此闭环

## 三、理论支撑

| 环节 | 理论 | 应用方式 |
|---|---|---|
| 拆解 | 微习惯 / Tiny Habits（Fogg） | 强制拆到 30 秒粒度 |
| 触发 | 实施意图 Implementation Intention（Gollwitzer） | 「在我 ___ 之后，我就 ___」句式，实证可提升执行率 2-3 倍 |
| 执行 | 福格行为模型 B = MAP | 行为 = 动机 × 能力 × 提示，缺哪个补哪个 |
| 反馈 | 习惯回路 Cue-Routine-Reward | 完成即庆祝，闭合回路 |
| 身份 | 身份型习惯（Atomic Habits） | 「每一次行动都是给你想成为的人投一票」 |
| 中断重启 | 习惯中断研究 | 断了不清零，提供「最小重启动作」 |
| 社会支持 | 社会支持理论 | 卡住时主动引导找人，而非独自硬扛 |

> 界面上**不出现任何理论名词**（沿用入口 A 铁律）。

## 四、功能需求

### 4.0 入口与衔接

**三种进入方式**：

| 方式 | 场景 | 输入 |
|---|---|---|
| A. 从洞察接力（**主路径**） | 入口 A 产出页新增按钮「把它变成行动 →」 | 自动带入 `scenario / essence / nearScenario.plan / resourcesPlan` |
| B. 从档案接力 | 档案页每张卡片新增「变成行动」按钮 | 同上，取历史 session |
| C. 独立开始 | 首页入口 B 卡片直接进入 | 用户自己写「想改变什么」 |

**首页改造**：入口 B 卡片去掉「即将上线」badge，改为可点击，与入口 A 平级。

---

### 4.1 Step 1 · 拆解（把大事拆到不可能失败）

**目标**：把「我想改变 X」拆成一个 30 秒就能做完的动作。

**交互**：

1. **确认要改变什么**（若从入口 A 带入则预填）
   - 「你想改变什么？」— 一句话
2. **拆成阶梯**（3-5 级）
   - 引导语：「假设这件事最终做成的样子是 100 分，倒着往回推，什么是 1 分的版本？」
   - 用户填写阶梯，或点「让知行帮我拆」
   - 呈现为可视化台阶（1 分 → 100 分）
3. **锁定第一级 = 微行动**
   - 用户从阶梯里选最小一级
   - **强制校验**：「这个动作，30 秒能做完吗？」
     - 选「能」→ 通过
     - 选「不能」→ 弹出「再小一点」引导，必须继续拆（最多可拆 3 轮，第 3 轮 AI 直接给候选）
   - 微行动示例库（引导用）：「打开文档写一行字」「翻开书读一段」「给对方发一句话」

**产出**：`steps[]` 阶梯 + `tiny { text, seconds }` 微行动

**AI 能力**：
- **帮我拆解**：把目标拆成 3-5 级递进阶梯，只拆不评价
- **帮我缩小**：把当前动作缩到 30 秒版本，给 3 个候选

**进展信号**：「已经小到不可能失败 ✓」

---

### 4.2 Step 2 · 触发 + 执行（现在就做一次）

**目标**：绑定一个真实存在的日常锚点，并**立刻执行第一次**。

**交互**：

1. **找锚点（实施意图）**
   - 句式卡：**「在我 ______ 之后，我就 ______」**
   - 前半段 = 已存在的日常动作，提供选择器：
     - 起床后 / 刷完牙 / 倒完第一杯水 / 打开电脑 / 吃完午饭 / 通勤坐下 / 洗完澡 / 躺上床
     - 或自定义
   - 后半段 = Step 1 锁定的微行动（自动带入）
   - **校验**：锚点必须是「每天都会发生」的事，AI 可提示风险（如「加班后」不稳定）
2. **准备提示**（可选）
   - 「需要给自己留个提示吗？」→ 便签/手机备忘/环境布置（如把书放枕头上）
3. **立刻做一次**（关键设计）
   - 大按钮：**「现在就做，我等你 30 秒」**
   - 点击后进入 30 秒倒计时全屏页（唯一使用倒计时的地方，且是正向的）
   - 倒计时结束 → 「做完了」/「没做完，再来一次」
4. **庆祝设定**
   - 「做完的那一刻，你怎么给自己一个确认？」
   - 预设：握拳说「就是这样」/ 深呼吸一次 / 打个勾 / 对自己笑一下
   - 说明文案：「这不是仪式感，是让大脑记住这件事是好的」

**产出**：`anchor { after, then }` + `celebration` + 首次执行记录

**AI 能力**：
- **帮我找锚点**：根据微行动和用户描述的日常，推荐 3 个高稳定性锚点
- 校验锚点稳定性并提示风险

**进展信号**：「第一票已投 · 你已经是那样的人了」

---

### 4.3 Step 3 · 反馈（让改变可见）

**目标**：持续追踪 + 难度自适应 + 中断不清零。

**交互**：

1. **行动卡片（常驻）**
   - 显示：微行动文本 / 锚点句 / 连续天数 / 本周完成格子
   - 主按钮：**「做完了」**（一键，不需要填任何东西）
   - 点击后：庆祝动画 + 「第 N 票已投给『___ 的人』」
2. **每次完成后的 3 秒微反馈**（可跳过）
   - 「刚才难吗？」→ 太容易 / 刚好 / 有点难
   - 根据反馈自适应：
     | 反馈 | 系统响应 |
     |---|---|
     | 连续 3 次「太容易」 | 建议升级到阶梯下一级 |
     | 「刚好」 | 保持 |
     | 连续 2 次「有点难」 | 建议缩小或换锚点 |
3. **没做到时**（核心差异化）
   - **不显示任何红色/失败/中断提示**
   - 显示诊断卡：「昨天没做成，是哪种情况？」
     | 用户选择 | 对应 B=MAP | 系统响应 |
     |---|---|---|
     | 忘了 | Prompt 缺失 | 换锚点 / 加提示 |
     | 太麻烦 | Ability 不足 | 缩小微行动 |
     | 不想做 | Motivation 不足 | 回看入口 A 的洞察，重连意义；或问「这件事还值得做吗」 |
     | 没时间 | Prompt 时机错 | 换到更稳定的锚点 |
   - **每种情况都直接给出一键修改入口**，不做说教
4. **中断重启**
   - 断 ≥3 天时，不清零 streak，显示「回来了，从最小的一步重新开始」
   - 提供「最小重启动作」= 当前微行动再缩小一半
5. **社会支持**（连续 2 次卡住时触发）
   - 「这件事你一个人扛了 N 天了，要不要找个人？」
   - 引导写：找谁 / 说什么 / 什么时候说
   - 自动带入入口 A 产出的 `resourcesPlan.people`

**产出**：`logs[]` + `streak` + 身份票累计

---

### 4.4 产出与档案整合

**行动毕业（graduated）**：
- 连续 21 次完成或用户手动标记 → 该行动「毕业」
- 毕业页：本次改变摘要 + 累计票数 + 身份陈述强化
- 「你已经为『___ 的人』投了 21 票。这不再是你想成为的人，这就是你。」

**档案页改造（archive.html）**：
- 顶部 tab 切换：**「想清楚过的」/「做到过的」**
- 「做到过的」展示行动卡列表（进行中 / 已毕业）
- 身份卡的票数 = 入口 A 的会话数 + 入口 B 的完成次数（合并计票）

## 五、数据模型

```javascript
// 新增 localStorage key
trf_actions          // 行动数组

Action {
  id, createdAt,
  sourceSessionId,          // 来自入口A的会话（可空，独立开始时为 null）
  goal,                     // 想改变什么（一句话）
  identity,                 // 关联的身份陈述（从入口A带入或新写）

  // Step 1 拆解
  steps: [ { level, text } ],       // 1分→100分阶梯
  tiny: { text, seconds },          // 锁定的微行动（seconds ≤ 30）
  shrinkRounds,                     // 拆了几轮（用于分析）

  // Step 2 触发
  anchor: { after, then, stability },  // stability: high|medium|low
  reminderNote,                        // 环境提示（可选）
  celebration,                         // 庆祝动作

  // Step 3 反馈
  logs: [ {
    date, done,                     // true=完成 false=未完成
    difficulty,                     // easy|just_right|hard（可空）
    blockReason,                    // forgot|too_hard|no_will|no_time（未完成时）
    note
  } ],
  streak, bestStreak, totalDone,
  status,                           // active | paused | graduated
  graduatedAt,
  supportPlan: { who, what, when }  // 社会支持（可空）
}

// 复用已有
trf_profile.identityStatements     // 入口B每次完成也 push 一票（source: 'action'）
```

**与入口 A 的数据契约（P0 必须先定）**：

```javascript
// 入口 A 产出页 → 入口 B 的交接对象
handoff = {
  sourceSessionId,
  goal:      session.scenario,                     // 想改变什么的初始值
  insight:   session.essence.insight,              // 为什么要改（重连意义用）
  planHint:  session.nearScenario.plan,            // 拆解的起点提示
  identity:  session.identity,                     // 身份
  people:    session.resourcesPlan.people          // 社会支持候选
}
// 传递方式：sessionStorage key `trf_handoff`，act.html 读取后清除
```

## 六、AI 能力设计（知行在入口 B）

| # | 能力 | 步骤 | Prompt 核心要求 | 边界 |
|---|---|---|---|---|
| 1 | 帮我拆解 | 拆解 | 「把目标拆成 3-5 级递进阶梯，第 1 级必须 30 秒内可完成，只拆解不评价不鼓励」 | 用户可全改 |
| 2 | 帮我缩小 | 拆解 | 「把这个动作缩到 30 秒版本，给 3 个候选，每个都具体到可立刻执行」 | 用户选或自己写 |
| 3 | 帮我找锚点 | 触发 | 「基于用户描述的日常，推荐 3 个每天必然发生的锚点，标注稳定性」 | 用户可自定义 |
| 4 | 卡住诊断 | 反馈 | 「用户连续未完成，基于其选择的原因，给出 1 个具体调整建议，不说教不鼓励」 | 只给一个建议 |
| 5 | 帮我找人 | 反馈 | 「基于用户的支持资源，建议找谁、说什么、什么时候说」 | 不代写消息 |

**严格禁止**：
- 任何形式的「加油/坚持/你可以的」
- 主动弹出、每日推送
- 替用户决定要不要继续这个行动

**复用**：直接复用 app.html 的 `aiCall()`（含 5 次退避重试）与设置页，无需重写。

## 九、验收标准

| # | 验收点 |
|---|---|
| 1 | 从入口 A 产出页可一键带数据进入入口 B，无需重复输入 |
| 2 | 微行动必须通过 30 秒校验才能进入下一步，不可绕过 |
| 3 | 锚点使用「在我 ___ 之后，我就 ___」句式，且可选日常锚点库 |
| 4 | 首次进入必须完成一次真实执行（30 秒倒计时），才算行动创建成功 |
| 5 | 「做完了」为一键操作，不强制填写任何内容 |
| 6 | 未完成时界面**不出现任何红色/失败/中断/催促**元素 |
| 7 | 未完成诊断给出的每个原因，都有对应的一键调整入口 |
| 8 | 断 ≥3 天不清零，提供缩小一半的重启动作 |
| 9 | 每次完成给身份投一票，与入口 A 的票数合并显示 |
| 10 | AI 输出中不含「加油 / 坚持 / 你可以的 / 建议你」等词 |
| 11 | AI 异常时全流程可手动完成，不阻塞 |
| 12 | 界面无任何理论术语（福格 / 实施意图 / 微习惯等） |

## 十、风险与应对

| 风险 | 应对 |
|---|---|
| 做成「又一个打卡 App」 | 差异化在三处：① 30 秒强制校验 ② 未完成时降难度而非催促 ③ 每次完成 = 身份投票 |
| 用户从入口 A 过来后不用 | 主路径按钮必须在产出页最显眼位置；带入数据必须完整，让用户「已经填好一半」 |
| 30 秒倒计时被当成压力 | 文案定调为「我等你」而非「限时」；未完成不惩罚，只问「要不要再小一点」 |
| 阶梯拆解太抽象用户填不出 | AI 一键拆解 + 示例库兜底；第 3 轮直接给候选 |
| 数据量增长导致 localStorage 溢出 | 沿用档案页导出机制；行动 logs 只存日期与枚举，不存长文本 |
| 与入口 A 的字段兼容问题 | P0 优先清理技术债，先统一再开发 |

## 十一、待确认决策

| # | 事项 | 建议 |
|---|---|---|
| 1 | 「毕业」阈值 21 次是否合适 | 建议 21 次（习惯研究常用区间），可在设置里改 |
| 2 | 是否支持同时进行多个行动 | **建议限 3 个**，超出提示「专注是有代价的」 |
| 3 | 每日提醒要不要做 | **建议不做**（沿用「AI 不打断」铁律），靠锚点而非通知 |
| 4 | 「做到过的」是否独立成页 | 建议先做 tab，数据量大了再拆页 |
| 5 | 入口 B 是否也需要 onboarding 引导卡 | 建议需要，一张即可 |
